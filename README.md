## 📅 Daily Breakdown

### Day 1-2: AWS Account Setup & Security Baseline

#### Day 1 Morning (2-3 hours): Initial Setup

**Step 1: Create AWS Account**
```bash
# If you don't already have an AWS account:
# 1. Go to https://aws.amazon.com
# 2. Click "Create an AWS Account"
# 3. Use a NEW email (not your existing one for isolation)
# 4. Enable billing alerts immediately
```

**Step 2: Secure the Root Account**
```bash
# DO IMMEDIATELY:
# 1. Enable MFA on root account (use Authenticator app)
#    - AWS Console → IAM → Dashboard → Add MFA
#    - Use Google Authenticator or Authy
# 2. Create root account access keys (if any exist) → DELETE them
# 3. Set up billing alerts:
#    - CloudWatch → Billing → Create Alarm
#    - Set threshold: $10, $50, $100
```

**Step 3: Create IAM Administrative User**
```bash
# Never use root account for day-to-day operations
# Create admin user with MFA:

# 1. IAM → Users → Add User
#    Username: your-admin-username
#    Access type: ✅ AWS Management Console access
#                 ✅ Programmatic access

# 2. Attach policy: AdministratorAccess (for learning; narrow later)

# 3. Enable MFA for this user

# 4. Save credentials securely:
aws configure --profile admin
# AWS Access Key ID: [your-key]
# AWS Secret Access Key: [your-secret]
# Default region: us-east-1
# Default output format: json

# 5. Test access:
aws sts get-caller-identity --profile admin
```

#### Day 1 Afternoon (2-3 hours): Security Logging Baseline

**Step 5: Enable CloudTrail**
```bash
# Enable CloudTrail for all regions (audit logging)

# Option A: Using AWS Console
# 1. CloudTrail → Dashboard → Create Trail
#    Name: security-audit-trail
#    Storage: Create new S3 bucket: cloudtrail-logs-[account-id]
#    ✅ Log file validation enabled
#    ✅ Enable for all regions
#    ✅ Enable for organization (if using Orgs)

# Option B: Using AWS CLI
aws cloudtrail create-trail \
    --name security-audit-trail \
    --s3-bucket-name cloudtrail-logs-$(aws sts get-caller-identity --query Account --output text) \
    --is-multi-region-trail \
    --enable-log-file-validation \
    --profile admin

# Start logging:
aws cloudtrail start-logging --name security-audit-trail --profile admin

# Verify:
aws cloudtrail get-trail-status --name security-audit-trail --profile admin
```

**Step 6: Secure the S3 CloudTrail Bucket**
```bash
# Apply bucket policy to prevent unauthorized access

# 1. S3 → Find your CloudTrail bucket
# 2. Block all public access (should be default)
# 3. Enable versioning
# 4. Enable encryption (SSE-S3 or SSE-KMS)
# 5. Enable Object Lock (optional, for compliance)

# CLI commands:
BUCKET_NAME="cloudtrail-logs-$(aws sts get-caller-identity --query Account --output text)"

# Block public access
aws s3api put-public-access-block \
    --bucket $BUCKET_NAME \
    --public-access-block-configuration \
    "BlockPublicAcls=true,IgnorePublicAcls=true,BlockPublicPolicy=true,RestrictPublicBuckets=true" \
    --profile admin

# Enable versioning
aws s3api put-bucket-versioning \
    --bucket $BUCKET_NAME \
    --versioning-configuration Status=Enabled \
    --profile admin

# Enable encryption
aws s3api put-bucket-encryption \
    --bucket $BUCKET_NAME \
    --server-side-encryption-configuration '{
        "Rules": [{
            "ApplyServerSideEncryptionByDefault": {
                "SSEAlgorithm": "AES256"
            }
        }]
    }' \
    --profile admin
```

**Step 7: Enable AWS Config**
```bash
# AWS Config tracks resource configurations and compliance

# 1. AWS Config → Get Started
# 2. ✅ Record all resources in this region
# 3. ✅ Include global resources (IAM, etc.)
# 4. Create S3 bucket: config-logs-[account-id]
# 5. Create IAM role (Config will auto-create)
# 6. ✅ Use managed rules:
#    - iam-password-policy
#    - cloudtrail-enabled
#    - s3-bucket-public-read-prohibited
#    - s3-bucket-public-write-prohibited
#    - root-account-mfa-enabled
#    - vpc-flow-logs-enabled

# Verify Config is recording:
aws configservice describe-configuration-recorder-status --profile admin
```

```bash
# Security Hub = Centralized security and compliance view

#    ✅ CIS AWS Foundations Benchmark v1.4
```

**Step 12: Create CloudWatch Alarms for Security Events**
```bash
# Set up alarms for critical security events

# Example: Alarm for Root Account Usage
aws cloudwatch put-metric-alarm \
    --alarm-name "RootAccountUsage" \
    --alarm-description "Alert when root account is used" \
    --metric-name "RootAccountUsage" \
    --namespace "CloudTrailMetrics" \
    --statistic Sum \
    --period 300 \
    --threshold 1 \
    --comparison-operator GreaterThanOrEqualToThreshold \
    --evaluation-periods 1 \
    --profile admin

# Create SNS topic for alerts:
aws sns create-topic --name security-alerts --profile admin

# Subscribe your email:
aws sns subscribe \
    --topic-arn arn:aws:sns:us-east-1:[ACCOUNT-ID]:security-alerts \
    --protocol email \
    --notification-endpoint your-email@example.com \
    --profile admin

# Confirm subscription via email link
```

**Step 13: CloudTrail Metric Filters**
```bash
# Create metric filters to monitor security events in CloudTrail

# Filter 1: Unauthorized API calls
aws logs put-metric-filter \
    --log-group-name /aws/cloudtrail/security-audit-trail \
    --filter-name UnauthorizedAPICalls \
    --filter-pattern '{ ($.errorCode = "*UnauthorizedOperation") || ($.errorCode = "AccessDenied*") }' \
    --metric-transformations \
        metricName=UnauthorizedAPICalls,metricNamespace=CloudTrailMetrics,metricValue=1 \
    --profile admin

# Filter 2: Console sign-in without MFA
aws logs put-metric-filter \
    --log-group-name /aws/cloudtrail/security-audit-trail \
    --filter-name ConsoleSignInWithoutMFA \
    --filter-pattern '{ ($.eventName = "ConsoleLogin") && ($.additionalEventData.MFAUsed != "Yes") }' \
    --metric-transformations \
        metricName=ConsoleSignInWithoutMFA,metricNamespace=CloudTrailMetrics,metricValue=1 \
    --profile admin

# Filter 3: IAM policy changes
aws logs put-metric-filter \
    --log-group-name /aws/cloudtrail/security-audit-trail \
    --filter-name IAMPolicyChanges \
    --filter-pattern '{($.eventName=DeleteGroupPolicy)||($.eventName=DeleteRolePolicy)||($.eventName=DeleteUserPolicy)||($.eventName=PutGroupPolicy)||($.eventName=PutRolePolicy)||($.eventName=PutUserPolicy)||($.eventName=CreatePolicy)||($.eventName=DeletePolicy)||($.eventName=CreatePolicyVersion)||($.eventName=DeletePolicyVersion)||($.eventName=AttachRolePolicy)||($.eventName=DetachRolePolicy)||($.eventName=AttachUserPolicy)||($.eventName=DetachUserPolicy)||($.eventName=AttachGroupPolicy)||($.eventName=DetachGroupPolicy)}' \
    --metric-transformations \
        metricName=IAMPolicyChanges,metricNamespace=CloudTrailMetrics,metricValue=1 \
    --profile admin
```

### Day 3-4: IAM Deep Dive

#### Day 3 Morning (2-3 hours): IAM Best Practices

**Step 14: Understand IAM Policy Structure**
```json
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Sid": "DescriptiveName",
      "Effect": "Allow",  // or "Deny"
      "Principal": {      // Who (for resource policies)
        "AWS": "arn:aws:iam::123456789012:user/username"
      },
      "Action": [         // What actions
        "s3:GetObject",
        "s3:PutObject"
      ],
      "Resource": [       // On which resources
        "arn:aws:s3:::my-bucket/*"
      ],
      "Condition": {      // Under what circumstances
        "IpAddress": {
          "aws:SourceIp": "203.0.113.0/24"
        }
      }
    }
  ]
}
```

**Step 15: Create Least-Privilege IAM Policies**
```bash
# Create a custom policy for read-only EC2 access

# Save this as ec2-read-only-policy.json:
cat > ec2-read-only-policy.json <<EOF
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Sid": "EC2ReadOnly",
      "Effect": "Allow",
      "Action": [
        "ec2:Describe*",
        "ec2:Get*",
        "ec2:List*"
      ],
      "Resource": "*"
    },
    {
      "Sid": "DenyDangerousActions",
      "Effect": "Deny",
      "Action": [
        "ec2:TerminateInstances",
        "ec2:DeleteSecurityGroup",
        "ec2:DeleteVolume"
      ],
      "Resource": "*"
    }
  ]
}
EOF

# Create the policy:
aws iam create-policy \
    --policy-name EC2ReadOnlyCustom \
    --policy-document file://ec2-read-only-policy.json \
    --description "Custom EC2 read-only access with explicit denies" \
    --profile admin
```

**Step 16: Implement IAM Permission Boundaries**
```bash
# Permission boundaries = Maximum permissions a user can have
# Useful for delegated administration

# Create permission boundary policy:
cat > permission-boundary.json <<EOF
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Sid": "AllowedServices",
      "Effect": "Allow",
      "Action": [
        "ec2:*",
        "s3:*",
        "cloudwatch:*",
        "logs:*"
      ],
      "Resource": "*"
    },
    {
      "Sid": "DenyHighRiskServices",
      "Effect": "Deny",
      "Action": [
        "iam:*",
        "organizations:*",
        "account:*"
      ],
      "Resource": "*"
    }
  ]
}
EOF

# Create policy:
aws iam create-policy \
    --policy-name DeveloperPermissionBoundary \
    --policy-document file://permission-boundary.json \
    --profile admin

# Apply to a user:
aws iam put-user-permissions-boundary \
    --user-name [username] \
    --permissions-boundary arn:aws:iam::[ACCOUNT-ID]:policy/DeveloperPermissionBoundary \
    --profile admin
```

#### Day 3 Afternoon (3-4 hours): IAM Roles for Services

**Step 17: Create IAM Role for EC2**
```bash
# Scenario: EC2 instance needs to write logs to CloudWatch

# 1. Create trust policy (who can assume this role):
cat > ec2-trust-policy.json <<EOF
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Effect": "Allow",
      "Principal": {
        "Service": "ec2.amazonaws.com"
      },
      "Action": "sts:AssumeRole"
    }
  ]
}
EOF

# 2. Create the role:
aws iam create-role \
    --role-name EC2-CloudWatch-Logs-Role \
    --assume-role-policy-document file://ec2-trust-policy.json \
    --description "Allows EC2 instances to write to CloudWatch Logs" \
    --profile admin

# 3. Attach policy (use managed policy):
aws iam attach-role-policy \
    --role-name EC2-CloudWatch-Logs-Role \
    --policy-arn arn:aws:iam::aws:policy/CloudWatchAgentServerPolicy \
    --profile admin

# 4. Create instance profile (EC2 requirement):
aws iam create-instance-profile \
    --instance-profile-name EC2-CloudWatch-Logs-Profile \
    --profile admin

# 5. Add role to instance profile:
aws iam add-role-to-instance-profile \
    --instance-profile-name EC2-CloudWatch-Logs-Profile \
    --role-name EC2-CloudWatch-Logs-Role \
    --profile admin
```

**Step 30: Create Lambda for Security Automation**
```bash
# Build Lambda function to auto-respond to GuardDuty findings

# 1. Create Lambda function code:
mkdir lambda-security-automation
cd lambda-security-automation

cat > lambda_function.py <<'EOF'
import json
import boto3
import os

def lambda_handler(event, context):
    """
    Auto-respond to GuardDuty findings
    - Log to CloudWatch
    - Send SNS alert
    - Take remediation action based on finding type
    """
    
    print(f"Received event: {json.dumps(event)}")
    
    # Parse GuardDuty finding
    detail = event.get('detail', {})
    finding_type = detail.get('type', 'Unknown')
    severity = detail.get('severity', 0)
    resource = detail.get('resource', {})
    
    # Initialize clients
    sns = boto3.client('sns')
    ec2 = boto3.client('ec2')
    
    # Determine action based on finding
    action_taken = "No action"
    
    if severity >= 7:  # High or Critical
        # Example: Isolate compromised EC2 instance
        if finding_type.startswith('UnauthorizedAccess:EC2'):
            instance_id = resource.get('instanceDetails', {}).get('instanceId')
            
            if instance_id:
                # Create isolation security group
                try:
                    # This is an example - in production, you'd have a pre-created SG
                    action_taken = f"Isolated instance {instance_id}"
                    print(f"Would isolate instance: {instance_id}")
                except Exception as e:
                    print(f"Error isolating instance: {e}")
    
    # Send SNS notification
    message = f"""
    GuardDuty Finding Alert
    
    Type: {finding_type}
    Severity: {severity}
    Action Taken: {action_taken}
    
    Full details: {json.dumps(detail, indent=2)}
    """
    
    try:
        sns.publish(
            TopicArn=os.environ['SNS_TOPIC_ARN'],
            Subject=f'GuardDuty Alert: {finding_type}',
            Message=message
        )
        print("SNS notification sent")
    except Exception as e:
        print(f"Error sending SNS: {e}")
    
    return {
        'statusCode': 200,
        'body': json.dumps({
            'finding_type': finding_type,
            'severity': severity,
            'action': action_taken
        })
    }
EOF

# 2. Create deployment package:
zip function.zip lambda_function.py

# 3. Create Lambda function:
aws lambda create-function \
    --function-name SecurityAutomationResponse \
    --runtime python3.11 \
    --role arn:aws:iam::[ACCOUNT-ID]:role/Lambda-Security-Automation-Role \
    --handler lambda_function.lambda_handler \
    --zip-file fileb://function.zip \
    --timeout 60 \
    --memory-size 256 \
    --environment "Variables={SNS_TOPIC_ARN=arn:aws:sns:us-east-1:[ACCOUNT-ID]:security-alerts}" \

cd ..
```
